7. 🚀 The Journey of One Request

What happens in about one second after a user clicks "My Orders".

  1. Browser: The user clicks a link or types a URL.
  2. DNS: Finds the IP address for the domain name.
  3. Edge (CDN + WAF): Serves cached files if it has them, and blocks attacks.
  4. Global Load Balancer: Chooses the closest or healthiest datacenter.
  5. Firewall: Lets only allowed traffic into the network.
  6. Load Balancer: Picks a healthy reverse proxy server.
  7. Reverse Proxy: Forwards the request to the Kubernetes cluster.
  8. Ingress: Sends screen requests to the frontend and /api requests to the backend.
  9. Backend: Checks the user's login, runs business rules.
  10. Cache / Database: Checks the cache first, then the database if needed.
  11. Queue (optional): Drops slow tasks, like "send confirmation email", in the queue.
  12. Response: JSON travels back the same way, and the browser shows it.

9. 📄 Two Ways to Build Web Pages: SPA vs MPA

Single Page Application (SPA)

The page loads once. After that, only data (JSON) is fetched, and JavaScript updates the screen.

Feels like: a mobile app, fast and smooth.
Examples: Angular, React, Vue apps. Gmail, Trello.

Multi Page Application (MPA)

Every click asks the server for a whole new page. The browser reloads each time.

Feels like: a classic website.
Examples: JSP, PHP, Django templates. Wikipedia, many blogs.

There is also Server-Side Rendering (SSR), which mixes both: the first page arrives ready-made for speed and search engines, then it behaves like an SPA. Examples: Next.js, Angular SSR, Nuxt.

11. 🛡️ Security Layers (Defense in Depth)

Like a castle with walls, guards and locked rooms, each layer catches what the previous one missed.

Layer 1: DDoS Protection + WAF
Blocks floods and attacks on the internet
Layer 2: Network Firewall
Only allowed IPs and ports get in
Layer 3: HTTPS / TLS
Data is encrypted while travelling
Layer 4: Authentication
Only logged-in, allowed users get access
Layer 5: Zone Firewalls
DMZ → App → Data
Layer 6: Secrets + Encryption
Protects the data itself

13. 🩺 Maintaining a Live Application

The Three Pillars of Observability

📊 Metrics

Numbers over time. CPU, memory, response time.
"How is it doing?"
Prometheus, Grafana, Dynatrace

📜 Logs

Written records of events and errors.
"What exactly happened?"
Splunk, ELK

🧵 Traces

One request's full path across all services.
"Where is it slow?"
Dynatrace, Jaeger, Zipkin

The Incident Loop

👀 Monitor
→
🔔 Alert
"Page is slow!"
→
🔍 Investigate
metrics, logs, traces
→
🔧 Fix
code or config
→
🚀 Deploy
→
📝 Learn
post-mortem
Example: Dynatrace alerts that the orders page went from 0.3 s to 5 s → Splunk logs show "database connection timeout" → the team fixes a slow SQL query → deploys → monitors again.

Regular Maintenance Tasks

  • Apply security patches to operating systems, libraries and frameworks
  • Renew SSL certificates before they expire
  • Test backups by actually restoring them
  • Run disaster recovery drills (switch to the other datacenter)
  • Review capacity: add servers before traffic grows

14. 💡 Key Concepts Every Student Should Know

ConceptSimple Meaning
IP AddressA computer's "house number" on a network, e.g., 142.250.1.1
PortA "door number" on a computer. HTTPS uses 443, HTTP uses 80.
HTTP / HTTPSThe language browsers and servers use. HTTPS is the encrypted version.
LatencyThe delay for data to travel. Lower is better.
Vertical ScalingMake one server bigger (more CPU and memory). Has limits.
Horizontal ScalingAdd more servers. Preferred for large apps.
High AvailabilityThe app keeps working even if some parts fail.
Health CheckA load balancer regularly asking a server "Are you alive?"
Active / ActiveTwo datacenters both serve users at the same time.
Active / PassiveOne serves users; the other waits as a backup.
ReplicationKeeping copies of data on more than one server.
RollbackGoing back to the previous working version after a bad release.
Single Point of FailureOne part that, if it breaks, breaks everything. Good design removes these.

15. ✅ Check Your Understanding

Click each question to reveal the answer.

1. What is the difference between the frontend and the backend?The frontend is what the user sees and runs in the browser (Angular, React). The backend runs on a server, handles business logic and talks to the database (Spring Boot, Node.js).
2. What does DNS do?It works like a phonebook: it converts a domain name like myshop.com into an IP address.
3. Why do we need a load balancer?To spread users across several servers so none is overloaded, and to stop sending traffic to servers that have failed.
4. What is the difference between a firewall and a WAF?A firewall checks where traffic comes from and which port it uses. A WAF looks inside web requests for attacks such as SQL injection.
5. Why put slow tasks in a message queue?So the user gets a quick response while a worker does the slow task (like sending an email) in the background.
6. What is a container, and what does Kubernetes do?A container packages an app with everything it needs. Kubernetes runs many containers, restarts failed ones and adds more when traffic grows.
7. Name the three pillars of observability.Metrics (numbers), logs (written records) and traces (the path of one request).
8. Why use two datacenters?For high availability. If one datacenter fails, users are automatically sent to the other.
9. What is an SPA?A Single Page Application loads the page once and then updates only the data using JavaScript, making it fast and app-like.
10. What should you always have before deploying to production?Tested code, a code review, monitoring in place and a rollback plan.
